macha

Job applications from one profile of facts, run through Claude Code.

What it is

A set of Claude Code skills that apply to jobs. Every resume, cover letter and form answer is written for the job at hand, from one file of facts about the person applying, profile.txt. One fact sits on one line, and each fact is written once.

  • Nothing is made up. Every claim in every document comes from a line of the profile. A requirement that no line covers is listed as a gap, never turned into a sentence.
  • The profile learns. When a job asks for something the profile doesn't say, macha asks. The answer goes into the profile and is committed before any document uses it. Corrections go the same way.
  • The profile stays honest. After every run, it is checked for lines that contradict each other, facts said twice, lines that hold two facts, words that read as a limit, and copies outside the file. The check finds the problem; the person says what is true.
  • No application goes out without a yes. The person approves twice: the drafts before the form is filled, and the filled form before it is sent.
  • A listing is a lead, the posting is the fact. Every job is checked open at its source and against every posting already seen, before it is offered.
  • Every job is a note. It sits in the journal's queue while it waits and is closed with what happened: applied, found closed, or skipped and why.

How it works

/job:apply takes one job from the queue, or searches company boards, HN Who's Hiring, remote job boards and LinkedIn when the queue is empty. Then:

  1. Read the posting, all of it.
  2. Ask for any fact it weighs that the profile lacks, and write the answer to the profile.
  3. Draft a gap analysis, a one-page resume and a cover letter, then reread them as the hiring manager would.
  4. You approve the drafts, or revise them.
  5. Fill the form: the PDFs, the answers, every value read back.
  6. You approve the form, and only then is it sent.
  7. Close the job's note with what happened, and check the profile.

The digests

Three more skills read one source each, rank what matters in it, and email the list, with the day's main point as the subject. A timer can run each one at 07:00 every day.

  • /news:digest ranks a story by how many outlets carry it, in how many countries. No single outlet's choice decides. A story only one outlet carries is left out, unless it's science and the paper behind it is found and linked.
  • /painpoints:digest collects the week's questions on Stack Exchange's everyday-life sites, groups the ones asking the same thing, ranks them by how many people ask and read, and says what a tool could do about each.
  • /linkedin:digest reads the LinkedIn feed and keeps what matters in it.

Use it

It needs Claude Code and the Playwright MCP server for the browser:

claude mcp add --scope user --transport stdio playwright -- npx -y @playwright/mcp \
  --isolated --storage-state ~/.config/playwright-mcp/state.json
cd macha && claude
/job:apply https://…

Write your own facts in jobs/profile/profile.txt, one to a line. The README covers the job log, the digests and their daily timers.

Edges

  • It runs in Claude Code, with a person at both approvals. It never sends an application on its own.
  • A site behind a login stops the run until you log in once. The login is saved for every later run.
  • LinkedIn's feed carries no post IDs, so a digest item links to its author's recent posts.
  • Reddit isn't a source: its API needs Reddit's approval first.
